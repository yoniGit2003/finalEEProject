# How to reproduce our results

Everything below is run from the **repository root** (the folder that holds this `docs/` folder), in the conda
environment of step 1. The commands are the same on Windows, Linux and macOS.

"Reproduce" means: the same procedure on the same data. The tables you get should match the committed ones up to the
last digits; two computers do not round identically, and one optional tool (PySR) uses a random search. The check in
step 6 shows you where your numbers differ from ours.

## The short version

```
conda env create -f environment.yml          # 1. the environment (once)
conda activate cmlpipe
python pipeline/get_data.py                  # 2. raw data from Zenodo (318 MB) + build the data release
python pipeline/get_caches.py                # 3. the saved fits (NOT PUBLISHED YET: skip it, step 4 then takes about 9 hours longer)
python -m research run all                   # 4. every research step, in order (about 20 minutes with the caches)
python docs/build_research_log.py            # 5. the research log PDF (needs LaTeX; optional)
python -m research compare                   # 6. your tables against the committed ones
```

## Step by step

### 1. The environment

`conda env create -f environment.yml`, then `conda activate cmlpipe`. This installs Python 3.12, the `cmlpipe`
package (the data layer, from `pipeline/`) and what the research scripts need (scipy, numba, pysindy, pysr).
`environment.lock.yml` lists the exact versions that produced the committed results; use it instead of
`environment.yml` if a newer package version gives different numbers.

PySR is only used by two optional cross-checks. On its first use it downloads Julia (about 1.2 GB). Without it those
rows are simply left out of the tables.

### 2. The data

`python pipeline/get_data.py` does two things:

1. downloads the public raw dataset OpenMRG v1.1 from Zenodo (https://doi.org/10.5281/zenodo.7107689), checks its
   md5 and unpacks it into `data/raw/openmrg/` (4.6 GB unpacked);
2. runs the pipeline, `python -m cmlpipe run all --workers 4`, which builds the work files in `data/work/openmrg/`
   and the data release in `data/release/openmrg_v1/`.

The build is long and can be interrupted: run the command again and finished stages are skipped. If Zenodo refuses
the download, get `OpenMRG.zip` in a browser, put it in `data/raw/` and run the script again. What the release
contains: [`../pipeline/docs/DATA_GUIDE.md`](../pipeline/docs/DATA_GUIDE.md).

### 3. The fit caches

**Not published yet.** The zip will be uploaded when the wet-antenna part is finished; until then
`python pipeline/get_caches.py` only says so, and the steps below fit again (the column "without caches").

Some wet-antenna steps fit many models to thousands of simulated drying tails. The first run of these steps took
about 9 hours in total on our computer. Every finished fit is saved, and `python pipeline/get_caches.py` downloads
those saved fits (one zip from a GitHub release of this repository) into `research/.cache/`. With them the same steps
run in seconds to minutes and read exactly the fits behind the committed tables.

Without the caches everything still works: the steps fit again (the column "without caches" below), and small
numerical differences in the fits are then possible.

### 4. The research steps

`python -m research` prints the menu below with the state of each step on your computer.
`python -m research run all` runs all of them in order; `python -m research run <step>` runs one;
`python -m research run all --from <step>` continues from a step. Every step can also be run directly with the
command in the table. Each step reads its settings from `research/config.yaml` and writes a report, tables and
figures into `research/<module>/outputs/`.

### 5. The research log

`python docs/build_research_log.py` builds `docs/research_log.pdf` from `docs/research_log.tex`. It needs a LaTeX
installation with `pdflatex` (MiKTeX or TeX Live). The committed PDF is already up to date, so this step is only
needed after you change the `.tex`. The same script builds `docs/project_structure.pdf` (what every folder and file
is): `python docs/build_research_log.py project_structure`.

### 6. Check your results

`python -m research compare` compares every table in `research/*/outputs/` on your disk with the committed version
and lists the columns that differ by more than a relative tolerance of 1e-9 (`--tolerance` changes it). Reports are
not compared, because they print run times. `git status` then shows which files changed at all.

## Everything else you can run

| command | what it does |
|---|---|
| `python -m cmlpipe stages` | list the pipeline stages in order |
| `python -m cmlpipe run all --workers 4` | build or update the data release (finished stages are skipped) |
| `python -m cmlpipe explore` | open the data explorer in the browser (localhost:8501) |
| `python -m research` | the menu of research steps |
| `python -m research run <step>` | run one research step (or `all`) |
| `python -m research compare` | your tables against the committed ones |
| `python -m research docs` | rewrite the step table on this page from `research/steps.yaml` |
| `python -m pytest` (in `pipeline/`) | the fast tests (about 1 minute, no data needed) |
| `python -m pytest -m data` (in `pipeline/`) | the tests that need the real data |
| `python pipeline/tools/check_boundaries.py` | check that research uses the data only through `cmlpipe.api` |
| `python docs/build_research_log.py` | build the research log PDF |

## Keeping this page right

The step table is generated from `research/steps.yaml`, the list that `python -m research` runs. After adding or
renaming a script: add its entry to `research/steps.yaml` and run `python -m research docs` (the `/updatedocs`
command of Claude Code does this too). A test (`pipeline/tests/test_research_steps.py`) fails, also on GitHub, if a
script is missing from the list or this page is out of date.
