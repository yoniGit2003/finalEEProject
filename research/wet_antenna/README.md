# wet_antenna: drying tails and a dynamic equation for wet-antenna attenuation (WAA)

## Purpose

A(t) = TL(t) - baseline = A_rain(t) + δ(t), where δ(t) is the non-rain part (WAA + baseline residual). In the
**drying tail** after the rain on a link has stopped, A_rain = 0, so A(t) = δ(t): what is left there is
mostly WAA. This module isolates WAA from the tails **before** f(L, R̄, Z) is learned. Otherwise a constant WAA looks
like f = L + L0. The later steps learn a dynamic model of the wetting / drying with weak-form SINDy (rain as input) and
compare it with the literature models [1], [9]. Tails are never selected by how well a model fits them (that would be
circular).

## Final equation (Part 1 closed, S9, 2026-10-19)

```
A(t) - c = W_f + W_s + L c_band R(t - 1 min)
dW_f/dt = (0.72 u - W_f) / tau_f   (tau_f 2.6 min wetting, 10.3 min drying)
dW_s/dt = (0.28 u - W_s) / 240 min
u = a_link A_band (R / 5)^b,  b = 0.54 [0.47, 0.63]
```

- A_band = 2.57 / 2.36 / 2.77 dB.
- c_band = 0.105 / 0.141 / 0.194 dB/km per mm/h (28 / 32 / 38 GHz).
- R = radar / g_e. Valid 0-40 mm/h.

## How to run

From the repository root: `python -m research` lists every step with its command and run time, and
`python -m research run <step>` runs one (full instructions: [`../../docs/REPRODUCE.md`](../../docs/REPRODUCE.md)).
Each script can also be run directly, e.g. `python -m research.wet_antenna.extract_tails`. Settings: section
`wet_antenna` of [`../config.yaml`](../config.yaml).

- Steps 0 to 3a read the data release and the baseline products. Steps 3b-1 to 4 read only files of this module.
  Step 4b reads the release again (radar, gauges, weather) and the cached fake datasets and fits of steps 3b-3b and 3b-3c.
  Step 4c reads the release (1 min tl_mean, link_state, radar, gauges), the baseline products (dew risk, dry jumps,
  daily-cycle amplitudes) and the two big files of steps 1 and 2b (`tails_1min.parquet`, `tails_selected.csv`); it fits nothing.
  Step 7a reads the release (1 min tl_mean of the links below 1 km, link_state, radar), `baselines.csv`, `tails_index.csv`,
  `tails_starts.csv` and `tails_1min.parquet`; it fits nothing and caches nothing.
- Step S1 reads the release (1 min tl_mean of the links below 1 km, link_state, radar on the path, City gauges), `baselines.csv`,
  `baseline_uncertainty.csv` and the noise table of the simulator; its fits (about 2.5 h on 3 processes) are cached in
  `research/.cache/wet_antenna/system_id_ladder/` and are saved stage by stage, so an interrupted run continues.
- Step S2 reads the same as S1 for the TRAIN links below 3 km; its fits (about 4.5 h on 3 processes; PySR for the naming)
  are cached in `research/.cache/wet_antenna/system_id_s2/`, stage by stage and every few folds, so an interrupted run continues.
- Step S2b reads the same as S2; its fits (about 4.5 h on 3 processes) are cached in `research/.cache/wet_antenna/system_id_s2b/`.
- Step S3 reads the S2b fits (never changes them) and the VAL events; its datasets and the S3.4 gauge refits (about 10 min the first time) are cached in `research/.cache/wet_antenna/system_id_s3/`.
- Step S3b reads the all-length datasets of S3; its fits (about 2.5 h on 3 processes) are cached in `research/.cache/wet_antenna/system_id_s3b/`.
- Step S4.1-S4.2 (`conditions_s4.py`) reads the S3 datasets and the frozen S3b fits (never changes them); its per-event results (about 6 min the first time) are cached in `research/.cache/wet_antenna/conditions_s4/`.
- Step S4.3 (`conditions_s4c.py`) reads the same data, the frozen S3b fits and the S4.1 factors table; its results (about 10 min the first time) are cached in `research/.cache/wet_antenna/conditions_s4c/`.
- Step S6 (`tighten_s6.py`) reads the S3 datasets, the S5a corrected TRAIN set and the S5a M4b-B fit and draws (read only); its jobs (about 1 h on 3 processes) are cached in `research/.cache/wet_antenna/tighten_s6/`.
- Step S7 (`validate_s7.py`) rebuilds the two frozen S6 fits from the S6 cache (read only) and caches its PySR runs (306, about 15 min on 3 processes) in `research/.cache/wet_antenna/validate_s7/`.
- Step S6b (`return_s6b.py`) caches every fit, fake replicate, fold and bootstrap draw (about 45 min on 3 processes the first time) in `research/.cache/wet_antenna/return_s6b/`.
- Step S8 (`test_s8.py`) runs twice: the first run fits B0-B2 (cached in `research/.cache/wet_antenna/test_s8/`) and writes the freeze file, which is committed; the second checks the hashes and reads TEST (its baselines and datasets are cached there too). `S8_DRYRUN=VAL` checks the evaluation code on VAL without reading TEST.
- Step S5a (`final_s5a.py`) reads the S3 datasets, the S4.3 g_e table and the frozen S3b fit; its fits (about 4 h the first time on 3 processes; every start and bootstrap draw saved) are cached in `research/.cache/wet_antenna/final_s5a/`.
- The steps that fit (3b-1 to 4b) save every finished fit in `research/.cache/wet_antenna/<script name>/`, so a second
  run takes seconds to minutes. `python pipeline/get_caches.py` downloads our saved fits; delete a folder to fit again.
- Three big files are not in git and are rebuilt by steps 1, 2 and 2b: `outputs/products/tails_1min.parquet` (47 MB),
  `outputs/products/tails_selected.csv` (17 MB) and `outputs/tables/check_per_tail_fit_fits.parquet` (18 MB, step 3b-1).
- Step 2 rewrites `tails_selected.csv` without the step 2b columns, so always run step 2b after step 2.

## Outputs

`outputs/products/` (the tail sets and the simulated tails that later steps read: `tails_index.csv`,
`tails_model*` = the frozen set v1, `tails_model_classes.csv` = the class of each TRAIN tail from step 4b, `tails_starts.csv` = the three candidate starts of every TRAIN pair from step 4c, `sim_tails_*`, `system_id_link_events.csv` = one row per link-event of step S1 with the held-out predictions of the chosen model, `system_id_s2_link_events.csv` = the same for the link-events of S2 below 3 km, with the set flags, `system_id_s2b_link_events.csv` = the same for S2b, with the chosen model, M3 and M4b), `outputs/tables/`, `outputs/figures/` and `outputs/reports/`.
Every file starts with the name of the script that writes it, and each script writes one report,
`outputs/reports/<script>.md`, which lists its tables and figures and explains them. Everything is committed except
the three big files above. The file locations are all in [`paths.py`](paths.py).
